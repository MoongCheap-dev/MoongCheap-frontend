# 라우트 맵 초안 (route map — draft)

> ⚠️ **이것은 확정된 화면 목록이 아니라 "예상 골격"입니다.** 와이어프레임·MVP 정보(디자인팀, 다음 주 예정)를 받으면 전면 갱신합니다.
> 백엔드 도메인 분할(A: 카탈로그·계정 / B: 거래·공동구매)과 서비스 컨셉(역경매형 공동구매)에서 유추한 **큰 구획**만 담았습니다. 세부 화면·실제 경로·파라미터는 미정입니다.

## 서비스 흐름 (요지)

소비자가 원하는 상품의 **수요를 등록** → 같은 수요가 모이면 **셀러들이 응찰** → 조건이 가장 좋은 응찰이 **자동 낙찰** → 주문·결제 → 정산.

- 사용자 역할(예상): **소비자(buyer)**, **셀러(seller)** — 화면 분기가 갈릴 수 있음 (미확정)

## 큰 구획

| 구획                   | 역할   | 주 소비 도메인                  | 비고                                                                                          |
| ---------------------- | ------ | ------------------------------- | --------------------------------------------------------------------------------------------- |
| **인증·계정**          | 공통   | A (인증, 회원)                  | 로그인/회원가입/로그아웃. 인증 방식 미확정 → [`security-baseline.md`](./security-baseline.md) |
| **수요 탐색·등록**     | 소비자 | A (상품, 검색) + B (공구 딜)    | 수요 목록/검색, 수요 등록, 수요 상세                                                          |
| **응찰**               | 셀러   | B (공구 딜, 참여)               | 셀러가 모인 수요에 응찰. 소비자 화면과 분리 가능성                                            |
| **낙찰·성사**          | 공통   | B (성사 판정)                   | 자동 낙찰 결과, 성사/미성사 상태                                                              |
| **장바구니·주문·결제** | 소비자 | B (장바구니, 주문, 결제)        | 결제는 PG 토큰화/iframe 전제 → [`security-baseline.md`](./security-baseline.md)               |
| **마이페이지**         | 공통   | A (회원, 알림) + B (참여, 정산) | 내 수요/응찰 내역, 정산(셀러), 알림                                                           |
| **검색**               | 공통   | A (검색)                        | 전역 검색. 수요 탐색과 통합될 수도                                                            |
| **AI 챗봇**            | 공통   | A (AI 챗봇)                     | 상담/추천. MVP 포함 여부 미확정                                                               |
| **알림**               | 공통   | A (알림)                        | 낙찰·성사·정산 등 이벤트 알림                                                                 |

## 확정 후 채울 것 (와이어프레임 수령 시)

- 각 구획의 실제 화면 목록과 경로(App Router 세그먼트)
- 소비자/셀러 역할 분기 방식 (별도 라우트 그룹 vs 조건부 렌더)
- 각 화면이 실제로 호출하는 API 엔드포인트 (백엔드 규격 확정 후)
- 공개/인증 필요 라우트 구분, 미들웨어 보호 범위
